## Architecture: Tick Processing

FT2 processes effects in a tick-based system. The `tickReplayer()` function is called periodically
from the audio callback.

### Tick 0 (New Row)

```
if (--song.tick == 0) {
    song.tick = song.speed;
    tickZero = true;
}

if (tickZero && pattDelTime2 == 0) {
    // Read new pattern data
    for each channel:
        getNewNote(ch, patternData);   // reads note, instrument, effects
        updateVolPanAutoVib(ch);       // envelope/auto-vibrato processing
} else {
    // Non-zero tick
    for each channel:
        handleEffects_TickNonZero(ch); // process ongoing effects
        updateVolPanAutoVib(ch);       // envelope/auto-vibrato processing
}

getNextPos(); // advance row on tick 1
```

### Key insight: tick counting

FT2 counts ticks **downward** from `speed` to 1. Tick 0 is when `song.tick` reaches 0
and is immediately reset to `song.speed`. The `song.tick` value during effect processing
represents the *remaining* ticks, not elapsed ticks.

For effects like ECx (Note Cut) and EDx (Note Delay), the comparison is:
```c
(uint8_t)(song.speed - song.tick) == param
```
This means param=0 fires on tick 0, param=1 on tick 1, etc.

### Samples per tick (BPM)

```
samplesPerTick = audioFreq / (BPM / 2.5)
```

## Period System and Frequency Conversion

FT2 uses a **period** system internally. Lower period = higher frequency.

### Note to Period (via lookup table)

```c
// noteIndex is computed from note number and finetune:
noteIndex = ((note - 1) * 16) + ((finetune >> 3) + 16);  // range 0..1935

// Lookup:
period = linearPeriodLUT[noteIndex];  // or amigaPeriodLUT[noteIndex]
```

### Linear Period Table

Generated by formula: `linearPeriodLUT[i] = (1936 - i) * 4`

So: C-0 at finetune 0 maps to index 16, giving period 7680. Each semitone is 64 period units
(16 finetune steps * 4 period units per step).

### Period to Frequency -- LINEAR MODE

```c
double dPeriod2Hz(uint32_t period) {
    period &= 0xFFFF;
    if (period == 0) return 0.0;

    uint32_t invPeriod = ((12 * 192 * 4) - period) & 0xFFFF;  // = 9216 - period
    uint32_t quotient  = invPeriod / (12 * 16 * 4);            // = invPeriod / 768
    uint32_t remainder = invPeriod % (12 * 16 * 4);            // = invPeriod % 768

    return dLogTab[remainder] * dExp2MulTab[(14 - quotient) & 31];
}
```

Where:
```c
dLogTab[i]    = 8363.0 * 256.0 * pow(2, i / 768.0)
dExp2MulTab[i] = 1.0 / pow(2, i)   // = pow(2, -i)
```

Simplified mathematical formula:
```
Hz = 8363 * 256 * 2^(remainder/768) * 2^(-(14 - quotient))
   = 8363 * 256 * 2^((invPeriod - 14*768) / 768)
   = 8363 * 256 * 2^((9216 - period - 10752) / 768)
   = 8363 * 2^8 * 2^((-1536 - period) / 768)
```

Or equivalently:
```
Hz = 8363 * 2^((6*12*16*4 - period) / (12*16*4))
   = 8363 * 2^((4608 - period) / 768)
```

### Period to Frequency -- AMIGA MODE

```c
Hz = (8363.0 * 1712.0) / period
```

Where 1712 is the Amiga period for C-4 at finetune 0, and 8363 is the C-4 sample rate.

### Period limits

- Minimum period: **1** (clamp in pitchSlideUp)
- Maximum period: **31999** (clamp in pitchSlideDown -- FT2 bug: uses signed comparison `(int16_t)period >= 32000`)

## Vibrato Sine Table

32 entries, representing a half-cycle of sine (0 to PI). Used for both vibrato and tremolo.

**Formula:** `vibratoTab[i] = floor(255 * sin(i * PI / 32))`

```
const uint8_t vibratoTab[32] = {
      0,  24,  49,  74,  97, 120, 141, 161,
    180, 197, 212, 224, 235, 244, 250, 253,
    255, 253, 250, 244, 235, 224, 212, 197,
    180, 161, 141, 120,  97,  74,  49,  24
};
```

Values range 0..255 (unsigned). The sign is determined by the vibrato position (see vibrato section).

### Auto-Vibrato Sine Table

256 entries (full cycle), values -64..+64 (signed).

**Formula:** `autoVibSineTab[i] = round(64 * sin(-i * 2 * PI / 256))`

## Arpeggio Table

```c
const uint8_t arpeggioTab[32] = {
    0, 1, 2, 0, 1, 2, 0, 1, 2, 0, 1, 2, 0, 1, 2, 0,

    // OVERFLOW BYTES from FT2's binary (confirmed identical in FT2.08 and FT2.09):
    0x00, 0x18, 0x31, 0x4A, 0x61, 0x78, 0x8D, 0xA1,
    0xB4, 0xC5, 0xD4, 0xE0, 0xEB, 0xF4, 0xFA, 0xFD
};
```

FT2 uses `arpeggioTab[song.tick & 31]`. The table is only valid for ticks 0..15
(speed <= 16). For speed >= 17, the overflow bytes (which are actually the start of the
vibratoTab in FT2's memory) produce unpredictable arpeggio behavior.

## Effect Memory System

Each effect with memory stores its last non-zero parameter in a **separate** channel variable.
When param=0, the stored value is recalled.

### Memory variables per channel (from `channel_t`)

| Variable | Used By | Shared? |
|---|---|---|
| `pitchSlideUpSpeed` | 1xx | Separate from E1x and X1x |
| `pitchSlideDownSpeed` | 2xx | Separate from E2x and X2x |
| `portamentoSpeed` | 3xx | Shared with volume column gxx (but gxx multiplied by 64) |
| `vibratoSpeed` | 4xy (speed nibble) | Separate |
| `vibratoDepth` | 4xy (depth nibble) | Separate |
| `tremoloSpeed` | 7xy (speed nibble) | Separate |
| `tremoloDepth` | 7xy (depth nibble) | Separate |
| `volSlideSpeed` | Axy, 5xy, 6xy | **Shared** among these three |
| `sampleOffset` | 9xx | Separate |
| `fPitchSlideUpSpeed` | E1x | Separate from 1xx and X1x |
| `fPitchSlideDownSpeed` | E2x | Separate from 2xx and X2x |
| `fVolSlideUpSpeed` | EAx | Separate from EBx |
| `fVolSlideDownSpeed` | EBx | Separate from EAx |
| `efPitchSlideUpSpeed` | X1x | Separate from 1xx and E1x |
| `efPitchSlideDownSpeed` | X2x | Separate from 2xx and E2x |
| `panningSlideSpeed` | Pxy | Separate |
| `noteRetrigSpeed` | Rxy (speed nibble) | Separate |
| `noteRetrigVol` | Rxy (vol nibble) | Separate |
| `tremorParam` | Txy | Separate |
| `globVolSlideSpeed` | Hxy | Separate |

### IMPORTANT: 1xx, 2xx, E1x, E2x, X1x, X2x all have SEPARATE memory

This is confirmed by the OpenMPT test case `Porta-LinkMem.xm`. Each of the six portamento
effects stores its speed independently.

## Effect Reference by Number

### 0xy Arpeggio

**Tick 0:** `ch->outPeriod = ch->realPeriod` (plays base note)

**Ticks 1+:**
```c
uint8_t tick = arpeggioTab[song.tick & 31];
if (tick == 0)
    ch->outPeriod = ch->realPeriod;        // base note
else if (tick == 1)
    noteOffset = param >> 4;                // first semitone offset (x)
else  // tick == 2
    noteOffset = param & 0x0F;             // second semitone offset (y)

ch->outPeriod = period2NotePeriod(ch->realPeriod, noteOffset, ch);
```

The `period2NotePeriod()` function uses a binary search through the period LUT to find the
note closest to `realPeriod`, then offsets by `noteOffset` semitones (each semitone = 16 LUT entries).

**Memory:** None. param=0 means no arpeggio (the `if (efx == 0 && param == 0) return;` check
in `handleEffects_TickNonZero` skips processing).

**Edge cases:**
- Arpeggio cycles are relative to `realPeriod` (after portamento), not the original note.
- When entering a new row, if the previous row had arpeggio, `outPeriod` is reset to `realPeriod` on tick 0.
- For speed >= 17, the overflow in `arpeggioTab` reads garbage data (FT2 bug).
- The binary search in `period2NotePeriod` only goes up to `8*12*16` (96 notes), not `10*12*16` -- FT2 bug.

### 1xx Portamento Up

**Tick 0:** No effect (only stores parameter if memory recall needed).

**Ticks 1+:**
```c
if (param == 0)
    param = ch->pitchSlideUpSpeed;
ch->pitchSlideUpSpeed = param;

ch->realPeriod -= param * 4;           // subtract param*4 from period
if ((int16_t)ch->realPeriod < 1)
    ch->realPeriod = 1;                // clamp to minimum period 1

ch->outPeriod = ch->realPeriod;
```

**Memory:** `pitchSlideUpSpeed` -- separate from E1x (`fPitchSlideUpSpeed`) and X1x (`efPitchSlideUpSpeed`).

**Key detail:** The speed is multiplied by 4. So `1xx` with param=1 slides 4 period units per tick.
In linear mode, 4 period units = 1/16 of a semitone per tick.

**Period limits:** Minimum 1 (signed comparison), maximum unbounded going up (but already at minimum).

---

### 2xx Portamento Down

**Tick 0:** No effect.

**Ticks 1+:**
```c
if (param == 0)
    param = ch->pitchSlideDownSpeed;
ch->pitchSlideDownSpeed = param;

ch->realPeriod += param * 4;           // add param*4 to period
if ((int16_t)ch->realPeriod >= 32000)  // FT2 BUG: signed comparison
    ch->realPeriod = 32000 - 1;        // clamp to 31999

ch->outPeriod = ch->realPeriod;
```

**Memory:** `pitchSlideDownSpeed` -- separate from E2x and X2x.

**FT2 Bug:** Uses `(int16_t)ch->realPeriod >= 32000` which is a signed comparison on an unsigned
uint16_t. Values 32768-65535 appear negative in signed comparison and pass the check.

---

### 3xx Tone Portamento

**Tick 0 (in `getNewNote`):**
```c
// Store portamento speed (multiplied by 4):
if (efxData != 0)
    ch->portamentoSpeed = efxData * 4;

// Set target from note in pattern:
noteIndex = ((note - 1 + relativeNote) * 16) + ((finetune >> 3) + 16);
ch->portamentoTargetPeriod = note2PeriodLUT[noteIndex];

// Determine direction:
if (targetPeriod == realPeriod)
    ch->portamentoDirection = 0;        // already at target
else if (targetPeriod > realPeriod)
    ch->portamentoDirection = 1;        // slide down (increase period)
else
    ch->portamentoDirection = 2;        // slide up (decrease period)
```

**CRITICAL:** The note in the pattern is NOT triggered -- it only sets the target. The
`triggerNote()` function is bypassed for effects 3 and 5. But if an instrument number is
present, volumes and envelopes ARE reset via `resetVolumes()` and `triggerInstrument()`.

**Ticks 1+:**
```c
if (ch->portamentoDirection == 0) return;  // no target or at target

if (ch->portamentoDirection > 1) {     // sliding up (target < current)
    ch->realPeriod -= ch->portamentoSpeed;
    if ((int16_t)ch->realPeriod <= (int16_t)ch->portamentoTargetPeriod) {
        ch->portamentoDirection = 1;   // reached target
        ch->realPeriod = ch->portamentoTargetPeriod;
    }
} else {                               // sliding down (target > current)
    ch->realPeriod += ch->portamentoSpeed;
    if (ch->realPeriod >= ch->portamentoTargetPeriod) {
        ch->portamentoDirection = 1;   // reached target
        ch->realPeriod = ch->portamentoTargetPeriod;
    }
}

if (ch->semitonePortaMode)             // E3x glissando
    ch->outPeriod = period2NotePeriod(ch->realPeriod, 0, ch);
else
    ch->outPeriod = ch->realPeriod;
```

**Memory:** `portamentoSpeed` -- speed is stored and recalled when param=0.
The target period and direction persist until a new note sets a new target.

**Edge cases:**
- `portamentoDirection` is set to 1 (== reached target) when target is reached, NOT 0.
  Direction 0 means "no target set at all."
- After reaching target, `portamentoDirection` stays at 1. If a subsequent 2xx (Porta Down)
  is followed by a 3xx, FT2 will try to slide down but immediately clamp to target (OpenMPT
  test `PortaResetDirection.xm`).

### 4xy Vibrato

**Tick 0:** Only stores parameters (if non-zero):
```c
// In vibrato() which runs on non-zero ticks:
if (param > 0) {
    uint8_t depth = param & 0x0F;
    if (depth > 0)
        ch->vibratoDepth = depth;

    uint8_t speed = (param & 0xF0) >> 2;  // NOTE: >>2, not >>4!
    if (speed > 0)
        ch->vibratoSpeed = speed;
}
```

**CRITICAL DETAIL:** The speed nibble is shifted right by 2 (not 4), so a speed value of
`x` in the effect becomes `x * 4` internally. This means vibrato speed range is 0..60 in steps of 4.

**Ticks 1+ (and tick 0 for vibrato continuation):**
```c
void doVibrato(channel_t *ch) {
    uint8_t tmpVib = (ch->vibratoPos >> 2) & 0x1F;  // 0..31 (table index)

    switch (ch->vibTremCtrl & 3) {
        case 0:  // sine
            tmpVib = vibratoTab[tmpVib];   // 0..255
            break;
        case 1:  // ramp down
            tmpVib <<= 3;                  // 0..248
            if ((int8_t)ch->vibratoPos < 0)
                tmpVib = ~tmpVib;          // invert (FT2-specific!)
            break;
        default: // square (2 and 3)
            tmpVib = 255;
            break;
    }

    tmpVib = (tmpVib * ch->vibratoDepth) >> 5;  // UNSIGNED shift right 5

    if ((int8_t)ch->vibratoPos < 0)
        ch->outPeriod = ch->realPeriod - tmpVib;
    else
        ch->outPeriod = ch->realPeriod + tmpVib;

    ch->vibratoPos += ch->vibratoSpeed;   // wraps at 256 (uint8_t)
}
```

**Vibrato position system:**
- `vibratoPos` is a uint8_t (0..255) representing a full cycle.
- The table index is `(vibratoPos >> 2) & 0x1F` giving 0..31 (the 32-entry table).
- The sign is determined by bit 7 of `vibratoPos`: positions 0..127 are positive half,
  128..255 are negative half.
- `vibratoSpeed` advances `vibratoPos` per tick. At speed=4 (param x=1), one full cycle
  takes 256/4 = 64 ticks.

**Depth formula:**
```
period_offset = (waveform_value * vibratoDepth) >> 5
```
Where `waveform_value` is 0..255. Maximum offset = `(255 * 15) >> 5 = 119` period units.
In linear mode, 119 period units = ~1.86 semitones.

**Phase reset:**
```c
// In triggerInstrument():
if (!(ch->vibTremCtrl & 0x04))  // bit 2 of low nibble
    ch->vibratoPos = 0;
```
Vibrato phase resets on new note UNLESS waveform type is 4..7 (continue mode, set via E4x).

**Memory:** Speed and depth stored separately. If only speed nibble is provided (y=0),
depth is unchanged. If only depth (x=0), speed is unchanged.

**Vibrato restoration:** When a row has vibrato and the next row does NOT have vibrato (4xy or 6xy),
`outPeriod` is reset to `realPeriod` on tick 0 of the new row. This is checked in `getNewNote()`.

### 5xy Tone Porta + Volume Slide

**Tick 0:** Only handles tone portamento target setup (via `preparePortamento`) and
volume column effects.

**Ticks 1+:**
```c
portamento(ch, 0);    // continue tone portamento (uses stored speed)
volSlide(ch, param);  // apply volume slide with param xy
```

**Memory:** Uses `portamentoSpeed` for the portamento (from last 3xx or 5xx with non-zero
portamento speed) and `volSlideSpeed` for the volume slide.

**IMPORTANT:** The param `xy` controls ONLY the volume slide. The portamento speed comes from
the previously stored `portamentoSpeed`. A `5xy` row does NOT update `portamentoSpeed` (see
`getNewNote`: for effect 5, the portamento speed is not updated: `if (efx != 5 && efxData != 0)`).

---

### 6xy Vibrato + Volume Slide

**Tick 0:** Volume column effects only.

**Ticks 1+:**
```c
doVibrato(ch);        // continue vibrato (uses stored speed/depth)
volSlide(ch, param);  // apply volume slide with param xy
```

**Memory:** Uses stored `vibratoSpeed`/`vibratoDepth` for vibrato and `volSlideSpeed` for volume slide.

### 7xy Tremolo

**Tick 0:** Only stores parameters (if non-zero):
```c
uint8_t depth = param & 0x0F;
if (depth > 0) ch->tremoloDepth = depth;

uint8_t speed = (param & 0xF0) >> 2;  // same >>2 as vibrato
if (speed > 0) ch->tremoloSpeed = speed;
```

**Ticks 1+:**
```c
uint8_t tmpTrem = (ch->tremoloPos >> 2) & 0x1F;

switch ((ch->vibTremCtrl >> 4) & 3) {
    case 0:  // sine
        tmpTrem = vibratoTab[tmpTrem];   // same table as vibrato!
        break;
    case 1:  // ramp
        tmpTrem <<= 3;
        if ((int8_t)ch->vibratoPos < 0)  // FT2 BUG: should be tremoloPos!
            tmpTrem = ~tmpTrem;
        break;
    default: // square
        tmpTrem = 255;
        break;
}

tmpTrem = (tmpTrem * ch->tremoloDepth) >> 6;  // NOTE: >>6, not >>5!

if ((int8_t)ch->tremoloPos < 0) {
    tremVol = ch->realVol - tmpTrem;
    if (tremVol < 0) tremVol = 0;
} else {
    tremVol = ch->realVol + tmpTrem;
    if (tremVol > 64) tremVol = 64;
}

ch->outVol = tremVol;
ch->tremoloPos += ch->tremoloSpeed;
```

**Key differences from vibrato:**
1. Depth shift is `>>6` (not `>>5`). Max offset = `(255 * 15) >> 6 = 59` volume units.
2. Modulates `outVol` (not `realVol`), so the base volume is preserved.
3. **FT2 BUG:** Ramp down waveform uses `ch->vibratoPos` instead of `ch->tremoloPos`
   for sign determination.
4. Volume is clamped to 0..64.
5. Waveform is controlled by upper nibble of `vibTremCtrl` (set via E7x).

**Phase reset:**
```c
// In triggerInstrument():
if (!(ch->vibTremCtrl & 0x40))  // bit 2 of high nibble (0x40 = bit 6)
    ch->tremoloPos = 0;
```

### 8xx Set Panning

**Tick 0:**
```c
ch->outPan = param;   // 0..255 (0=left, 128=center, 255=right)
```

**Ticks 1+:** No effect.

**Memory:** None.

**Edge case:** An instrument number on a subsequent row will reset panning to the sample's
default panning value (`ch->oldPan = s->panning`).

### 9xx Sample Offset

**Tick 0 (in `triggerNote()`):**
```c
if (efx == 9) {
    if (efxData > 0)
        ch->sampleOffset = ch->efxData;

    ch->smpStartPos = ch->sampleOffset << 8;  // offset * 256
}
```

**Memory:** `sampleOffset` -- stored and recalled when param=0. But ONLY updated when
`efxData > 0`. A 900 command uses the last stored offset.

**Edge cases:**
- Maximum offset: `0xFF << 8 = 65280` samples.
- If offset is beyond sample end, sample playback stops.
- Offset memory only updates when there is an actual note (not key-off).
- Without a note in the pattern cell, the offset has no effect.

### Axy Volume Slide

**Tick 0:** No effect (stores parameter for memory only).

**Ticks 1+:**
```c
if (param == 0)
    param = ch->volSlideSpeed;
ch->volSlideSpeed = param;

uint8_t newVol = ch->realVol;
if ((param & 0xF0) == 0) {
    // Slide down: lower nibble
    newVol -= param;
    if ((int8_t)newVol < 0) newVol = 0;
} else {
    // Slide up: upper nibble (takes priority)
    param >>= 4;
    newVol += param;
    if (newVol > 64) newVol = 64;
}

ch->outVol = ch->realVol = newVol;
```

**Priority rule:** If upper nibble is non-zero, slide UP. Only if upper nibble is 0,
slide down using lower nibble. This means `AFx` is an upward slide by 15 per tick
(the `x` is ignored).

**Memory:** `volSlideSpeed` -- SHARED between Axy, 5xy, and 6xy.

**Volume range:** 0..64.

---

### Cxx Set Volume

**Tick 0:**
```c
if (param > 64) param = 64;
ch->outVol = ch->realVol = param;
```

**Ticks 1+:** No effect.

**Memory:** None.

**Range:** 0..64 (values > 64 are clamped).

### E1x Fine Portamento Up

**Tick 0:**
```c
if (param == 0)
    param = ch->fPitchSlideUpSpeed;
ch->fPitchSlideUpSpeed = param;

ch->realPeriod -= param * 4;
if ((int16_t)ch->realPeriod < 1)
    ch->realPeriod = 1;

ch->outPeriod = ch->realPeriod;
```

**Ticks 1+:** No effect.

**Memory:** `fPitchSlideUpSpeed` -- SEPARATE from 1xx and X1x.

**Scale:** Same `* 4` multiplier as 1xx. So E1x with param 1 slides 4 period units,

### E2x Fine Portamento Down

**Tick 0:**
```c
if (param == 0)
    param = ch->fPitchSlideDownSpeed;
ch->fPitchSlideDownSpeed = param;

ch->realPeriod += param * 4;
if ((int16_t)ch->realPeriod >= 32000)  // FT2 bug: signed comparison
    ch->realPeriod = 32000 - 1;

ch->outPeriod = ch->realPeriod;
```

**Ticks 1+:** No effect.

**Memory:** `fPitchSlideDownSpeed` -- SEPARATE from 2xx and X2x.

### E4x Set Vibrato Waveform

**Tick 0:**
```c
ch->vibTremCtrl = (ch->vibTremCtrl & 0xF0) | param;
```

**Waveform types (lower 2 bits of param):**
- 0: Sine (default)
- 1: Ramp down (sawtooth)
- 2: Square
- 3: Square (same as 2)

**Retrigger control (bit 2 of param):**
- 0..3: Phase resets on new note
- 4..7: Phase continues on new note (does NOT reset)

---

### E7x Set Tremolo Waveform

**Tick 0:**
```c
ch->vibTremCtrl = (param << 4) | (ch->vibTremCtrl & 0x0F);
```

Same waveform types as E4x, stored in upper nibble of `vibTremCtrl`.

---

### E9x Retrigger Note

**Tick 0:** If `param == 0x90` (E90), the entire `getNewNote` note-handling is skipped and
the note is triggered immediately.

**Ticks 1+:**
```c
if (param == 0) return;  // E90 is handled at tick 0

if ((song.speed - song.tick) % param == 0) {
    triggerNote(0, 0, 0, ch);
    triggerInstrument(ch);
}
```

**Memory:** None (but E90 has special behavior).

**Note:** This is the simple retrigger. The more advanced Rxy (multi-retrig) has volume
modification (see separate section).

---

### EAx Fine Volume Slide Up

**Tick 0:**
```c
if (param == 0)
    param = ch->fVolSlideUpSpeed;
ch->fVolSlideUpSpeed = param;

ch->realVol += param;
if (ch->realVol > 64) ch->realVol = 64;
ch->outVol = ch->realVol;
```

**Ticks 1+:** No effect.

**Memory:** `fVolSlideUpSpeed` -- SEPARATE from EBx.

### EBx Fine Volume Slide Down

**Tick 0:**

```c
if (param == 0)
    param = ch->fVolSlideDownSpeed;
ch->fVolSlideDownSpeed = param;

ch->realVol -= param;
if ((int8_t)ch->realVol < 0) ch->realVol = 0;
ch->outVol = ch->realVol;
```

**Ticks 1+:** No effect.

**Memory:** `fVolSlideDownSpeed` -- SEPARATE from EAx.

### ECx Note Cut

**Tick 0:** Special handling:
```c
// In noteCut0() -- only called for EC0:
if (param == 0) {
    ch->realVol = 0;
    ch->outVol = 0;
}
```

**Ticks 1+:**
```c
if ((uint8_t)(song.speed - song.tick) == param) {
    ch->outVol = ch->realVol = 0;
}
```

**Memory:** None.

**Edge case:** If `param >= speed`, the cut never triggers. EC0 cuts immediately on tick 0.

---

### EDx Note Delay

**Tick 0:** When EDx is present (with x >= 1), the entire `getNewNote()` returns early:
```c
if (efxData >= 0xD1 && efxData <= 0xDF)
    return;  // skip all note/instrument processing
```

ED0 is NOT treated as a delay -- it is ignored, and normal note processing occurs.

**Ticks 1+:**
```c
if ((uint8_t)(song.speed - song.tick) == param) {
    triggerNote(note, 0, 0, ch);

    if (instrument > 0)
        resetVolumes(ch);

    triggerInstrument(ch);

    // Also handle volume column commands:
    if (volColumnVol >= 0x10 && volColumnVol <= 0x50)
        ch->outVol = ch->realVol = volColumnVol - 16;
    else if (volColumnVol >= 0xC0 && volColumnVol <= 0xCF)
        ch->outPan = (volColumnVol & 0x0F) << 4;
}
```

**Memory:** None.

**Edge cases:**
- ED0 is ignored (note plays normally on tick 0).
- If param >= speed, the note is never triggered.
- **Portamento + Note Delay:** Portamento effects adjacent to a note delay are ignored
  (OpenMPT test `porta-delay.xm`).
- If no note is present in the cell, the last played note is retriggered when EDx fires
  (OpenMPT test `delay2.xm`).

### Pxy Panning Slide

**Tick 0:** No effect.

**Ticks 1+:**
```c
if (param == 0)
    param = ch->panningSlideSpeed;
ch->panningSlideSpeed = param;

int16_t newPan = (int16_t)ch->outPan;
if ((param & 0xF0) == 0) {
    // Slide left: lower nibble
    newPan -= param;
    if (newPan < 0) newPan = 0;
} else {
    // Slide right: upper nibble (takes priority)
    param >>= 4;
    newPan += param;
    if (newPan > 255) newPan = 255;
}

ch->outPan = (uint8_t)newPan;
```

**Priority:** Same as volume slide: upper nibble (right) takes priority over lower nibble (left).

**Memory:** `panningSlideSpeed` -- separate from volume slide.

**Range:** 0..255.

**FT2 quirk:** Pan slide left with param=0 (P00 with stored speed 0) slides panning to 0
on all non-first ticks (OpenMPT test `PanSlideZero.xm`).

---

### X1x Extra Fine Portamento Up

**Tick 0:**
```c
if (param == 0)
    param = ch->efPitchSlideUpSpeed;
ch->efPitchSlideUpSpeed = param;

ch->realPeriod -= param;       // NO multiplication! Raw period units.
if ((int16_t)ch->realPeriod < 1)
    ch->realPeriod = 1;
ch->outPeriod = ch->realPeriod;
```

**Ticks 1+:** No effect.

**Memory:** `efPitchSlideUpSpeed` -- SEPARATE from 1xx and E1x.

**Key difference:** No `* 4` multiplication. X11 slides by 1 period unit (1/4 the resolution of E11).

## Pitch Modulation Combination

The final period used for frequency calculation combines multiple sources:

```
outPeriod = realPeriod +/- vibrato_offset   (from doVibrato)
finalPeriod = outPeriod +/- autoVibrato     (from updateVolPanAutoVib)
```

**Order of operations:**
1. `realPeriod` is modified by portamento (1xx, 2xx, 3xx) and fine porta (E1x, E2x, X1x, X2x).
2. `outPeriod` is set from `realPeriod`, then vibrato is ADDED/SUBTRACTED to get `outPeriod`.
3. `finalPeriod` is computed from `outPeriod` with auto-vibrato offset.
4. `finalPeriod` is what gets converted to frequency via `dPeriod2Hz()`.

**Arpeggio** sets `outPeriod` directly (replacing any vibrato) via `period2NotePeriod()`.

---

## Volume Modulation Combination

The final volume combines multiple sources:

```c
// In updateVolPanAutoVib():
int32_t vol = song.globalVolume * ch->outVol * ch->fadeoutVol;
float fVol = vol * (1.0f / (64.0f * 64.0f * 32768.0f));

if (volEnvEnabled)
    fVol *= fEnvVal * (1.0f / 64.0f);

ch->fFinalVol = CLAMP(fVol, 0.0f, 1.0f);
```

**Order of operations:**
1. `realVol` is modified by volume slide (Axy), set volume (Cxx), fine volume slide (EAx/EBx).
2. `outVol` is set from `realVol`, then tremolo modifies ONLY `outVol` (not `realVol`).
3. Final volume = `globalVolume (0..64) * outVol (0..64) * fadeoutVol (0..32768)`.
4. Volume envelope value (0..64) multiplies the result.
5. Panning is applied separately via pan law.

## Volume Column Effects

The XM volume column byte is encoded as ranges:

| Byte Range | Effect | Tick 0 | Ticks 1+ |
|---|---|---|---|
| 0x00 | Nothing | -- | -- |
| 0x10-0x50 | Set Volume (v-0x10) | Applied | -- |
| 0x60-0x6F | Volume Slide Down (v&0xF) | -- | Applied per tick |
| 0x70-0x7F | Volume Slide Up (v&0xF) | -- | Applied per tick |
| 0x80-0x8F | Fine Vol Slide Down (v&0xF) | Applied | -- |
| 0x90-0x9F | Fine Vol Slide Up (v&0xF) | Applied | -- |
| 0xA0-0xAF | Set Vibrato Speed ((v&0xF)*4) | Applied | -- |
| 0xB0-0xBF | Vibrato (depth=v&0xF) | -- | doVibrato() |
| 0xC0-0xCF | Set Panning ((v&0xF)<<4) | Applied | -- |
| 0xD0-0xDF | Pan Slide Left (v&0xF) | -- | Applied per tick |
| 0xE0-0xEF | Pan Slide Right (v&0xF) | -- | Applied per tick |
| 0xF0-0xFF | Tone Portamento ((v&0xF)<<4)*4 | Speed stored | portamento() |

### Volume Column Portamento (gxx)

```c
// Tick 0 in getNewNote():
uint8_t param = ch->volColumnVol & 0x0F;
if (param > 0)
    ch->portamentoSpeed = (param << 4) * 4;  // = param * 64

// This is 16x coarser than effect column 3xx
// (effect column: speed * 4, volume column: speed * 64)
```

### Volume Column Vibrato

The volume column vibrato (Bx) only sets depth, using the speed from the last 4xy
command's speed parameter. On non-zero ticks, it calls the same `doVibrato()` function.

**Double speed quirk:** If BOTH volume column vibrato AND effect column vibrato/vibrato+volslide
(4xx/6xx) are present, the vibrato position advances TWICE per tick (OpenMPT test `VibratoDouble.xm`).

### Volume Column Pan Slide Left (FT2 Bug)

```c
uint16_t tmp16 = ch->outPan + (uint8_t)(0 - (ch->volColumnVol & 0x0F));
if (tmp16 < 256)      // FT2 bug: pan-slide-left of 0 = set pan to 0
    tmp16 = 0;
ch->outPan = (uint8_t)tmp16;
```

When the slide amount is 0, the subtraction wraps to 256 (0 + 256 = 256 unsigned), which
is >= 256, so the `if` check does NOT trigger. But `(uint8_t)256 = 0`, so pan becomes 0.
This is an FT2 bug that causes D0 (pan slide left with value 0) to snap panning to hard left.

## Known FT2 Bugs Preserved in Clone

1. **Portamento down limit:** Uses signed comparison `(int16_t)period >= 32000`, meaning periods
   32768-65535 appear negative and pass the check.

2. **Tremolo ramp waveform:** Uses `ch->vibratoPos` instead of `ch->tremoloPos` for sign
   determination of ramp-down waveform.

3. **Arpeggio table overflow:** The `arpeggioTab` is only 16 entries for the valid `0,1,2`
   pattern. Speeds >= 17 read overflow bytes from adjacent data (the vibratoTab in FT2's
   original memory layout).

4. **period2NotePeriod range:** Binary search only goes to `8*12*16` (note 96) instead of
   `10*12*16`. Notes above B-7 with relative note offsets may misbehave.

5. **Panning envelope check:** In `keyOff()`, the panning envelope check uses
   `ins->volEnvFlags & ENV_SUSTAIN` instead of `ins->panEnvFlags`. This means the panning
   envelope sustain point is incorrectly checked based on the volume envelope's sustain flag.

6. **Pattern loop bug:** E60 (set loop start) causes the NEXT pattern to also start at
   the stored row instead of row 0.

7. **Volume column pan slide left with 0:** Results in hard-left panning due to unsigned
   arithmetic overflow (see volume column section).

## Rxy Multi-Note Retrigger (Advanced Retrigger)

**Tick 0:**
```c
// Store parameters with memory:
uint8_t speed = param & 0x0F;
if (speed == 0) speed = ch->noteRetrigSpeed;
ch->noteRetrigSpeed = speed;

uint8_t vol = param >> 4;
if (vol == 0) vol = ch->noteRetrigVol;
ch->noteRetrigVol = vol;

// Only retrigger on tick 0 if volume column data is 0
if (volumeColumnData == 0)
    doMultiNoteRetrig(ch, 0);
```

**Ticks 1+:**
```c
void doMultiNoteRetrig(channel_t *ch, uint8_t param) {
    uint8_t cnt = ch->noteRetrigCounter + 1;
    if (cnt < ch->noteRetrigSpeed) {
        ch->noteRetrigCounter = cnt;
        return;
    }
    ch->noteRetrigCounter = 0;

    // Volume modification table:
    int16_t vol = ch->realVol;
    switch (ch->noteRetrigVol) {
        case 0x1: vol -= 1; break;
        case 0x2: vol -= 2; break;
        case 0x3: vol -= 4; break;
        case 0x4: vol -= 8; break;
        case 0x5: vol -= 16; break;
        case 0x6: vol = (vol >> 1) + (vol >> 3) + (vol >> 4); break;  // vol * 11/16
        case 0x7: vol >>= 1; break;                                     // vol * 1/2
        case 0x8: break;  // no change
        case 0x9: vol += 1; break;
        case 0xA: vol += 2; break;
        case 0xB: vol += 4; break;
        case 0xC: vol += 8; break;
        case 0xD: vol += 16; break;
        case 0xE: vol = (vol >> 1) + vol; break;                        // vol * 3/2
        case 0xF: vol += vol; break;                                     // vol * 2
    }
    vol = CLAMP(vol, 0, 64);

    // Apply volume column override (if present):
    if (ch->volColumnVol >= 0x10 && ch->volColumnVol <= 0x50)
        ch->outVol = ch->realVol = ch->volColumnVol - 0x10;
    else if (ch->volColumnVol >= 0xC0 && ch->volColumnVol <= 0xCF)
        ch->outPan = (ch->volColumnVol & 0x0F) << 4;

    triggerNote(0, 0, 0, ch);
}
```
