# Historical Parameter → `ParamKind` Audit (Phase 0)

> **Purpose.** This is the Phase 0 snapshot that established the five value-kinds
> during the parameter-type-system work. The retired implementation plan is available
> in Git history. Current code is authoritative: each parameter enum's `kind()` method
> and the descriptor-invariant tests in `synth_modules::module_factory` must agree.
>
> **Provenance.** Generated by reading every `pub enum *Param` in
> `crates/synth_core/src/params/` and classifying each variant by its carried value
> type. The totals below describe that historical audit and are not a live module
> inventory. Supersedes the plan's *provisional* counts, which had no `Reference`
> bucket and over-counted `Enum`.
 
## Classification rules

A variant's kind is the kind of its **value-bearing carried type**:

| Carried type                                                                                                                                                                                                                 | `ParamKind`                                          |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------|
| f32-wrapping newtype (`Hertz`, `Gain`, `Decibels`, `Seconds`, `Milliseconds`, `Cents`, `Semitones`, `NormalizedValue`, `BipolarValue`, `Phase`, `Ratio`, `BeatDivision`, `TimeScale`, `PulseWidth`, `BitDepth`, `DecayTrim`) | **Continuous**                                       |
| raw `f32`                                                                                                                                                                                                                    | **Continuous** (should get a newtype — see findings) |
| integer primitive (`u8`/`i32`/`u32`/`usize`) **or integer-backed newtype** (`VoiceCount`, `MidiNote`, `Octaves`, `StepCount`)                                                                                                | **Integer**                                          |
| `bool`                                                                                                                                                                                                                       | **Bool**                                             |
| choice/mode enum (`Waveform`, `FilterMode`, …)                                                                                                                                                                               | **Enum**                                             |
| `SampleId`, `Option<SrcAddr>`, `Option<DestAddr>`                                                                                                                                                                            | **Reference**                                        |

For two-field variants `Variant(u8, T)` the kind is **T**'s kind; the leading `u8` is
a structural index/slot, not a parameter value.

## Findings (feed back into the plan)

1. **The taxonomy is complete** — all 378 variants fit one of the five kinds. No sixth
   kind is needed.
2. **The `Reference` bucket is exactly 3 variants:** `SamplerParam::SampleSelect`
   (`SampleId`), `ModMatrixParam::SlotSource` (`Option<SrcAddr>`),
   `ModMatrixParam::SlotDestination` (`Option<DestAddr>`). This is the bucket the
   plan's §0 flagged as unreconciled; here it is.
3. **Enum is 31, not the provisional ~107.** The earlier tally badly over-counted;
   there are only 31 choice-kind *param variants* (drawn from ~25 distinct choice
   enums). This shrinks the `impl_scalar_param_enum!` surface accordingly.
4. **Not every newtype is `Continuous` — integer-backed newtypes are `Integer`.**
   This is the key classification subtlety. `VoiceCount`, `MidiNote`, `Octaves`,
   `StepCount` wrap integers and must get `KIND = Integer` in their `ScalarParam`
   impls. The following variants were reclassified Continuous → Integer (marked **†**
   in the tables): `ChorusParam::Voices`, `EnsembleChorusParam::Voices`,
   `ModalResonatorParam::{BaseNote, Modes}`, `WavetableParam::Octave`.
   (`KeyboardPannerParam::CenterNote` was already Integer.)
    - **Watch the `Octaves` newtype vs the `SubOscOctave` enum:**
      `WavetableParam::Octave` carries the integer-backed `Octaves` newtype →
      **Integer**, but `SubOscParam::Octave` carries the `SubOscOctave` *enum* →
      **Enum**. Same display name, different kind.
5. **Two raw-`f32` params confirmed:** `KineticParam::{OutputVel, OutputAcc}` (read-out
   values). They classify Continuous but should get newtypes (tracked separately).
6. **Inconsistent `UnisonVoices` backing across modules:** `OscillatorParam::UnisonVoices`
   is `u8` (**Integer**), but `VoiceSynthParam::UnisonVoices` and
   `FofParam::UnisonVoices` are `NormalizedValue` (**Continuous**, a normalized macro).
   Not a bug, but note the divergence — a future cleanup might unify them.
7. **Verify `BitDepth`** (`DistortionParam::BitDepth`): classified Continuous assuming
   an f32-wrapping newtype (fractional bit depth for smooth bitcrush sweeps). Confirm
   the backing type during Phase 1; if it is integer-backed, move to Integer.
